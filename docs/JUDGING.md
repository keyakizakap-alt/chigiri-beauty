# Judging Criteria

| 審査項目 | CHIGIRIでの根拠 | デモで見せる内容 |
| --- | --- | --- |
| 課題の実在性 | 美容相談で起きる聞き直し、情報過多、商品先行を解決 | 条件を複数伝えても質問を繰り返さない |
| ビジネス成立性 | EC送客、ブランド連携、継続相談を拡張可能 | 手持ち優先から必要時だけ商品候補へ進む |
| 完成度・デモの説得力 | 5領域、履歴、画像、商品詳細、口コミ、異常系を一つの体験に統合 | 相談→パーソナルカラー確認→口コミ付き提案→履歴再開まで通す |
| AIである必然性 | 自由文から本人申告の条件と外部評価を統合し、文脈に応じた自然な返答をLLMが担当 | 色を写真から断定せず確認し、口コミ数値も出典付きで扱う |
| 技術的な作り込み | 構造化メモリ、D1、R2、OrcaRouter、公式データ制約 | アーキテクチャとフォールバックを説明 |
| LLMコスト | 初期聞き取りと安全停止はルール処理、提案段階のみLLM | LLMを呼ぶ段階と呼ばない段階を比較 |
| セキュリティ | サーバー側入力検証、秘密管理、所有者確認、医療安全ルール | 不正入力・強い症状・LLM障害時の挙動 |
| 次世代性・独創性 | 専門家分業＋会話メモリ＋公式情報に限定したハイブリッドAI | 5人の専門家が担当領域ごとに推論を変える |

## Three-minute demo

1. 0:00–0:25: 美容相談の課題とCHIGIRIの一文価値提案
2. 0:25–1:20: メイク相談で場面・質感・予算を一度に伝え、自然に提案へ進む
3. 1:20–1:45: ページ再読み込み後も相談履歴から再開する
4. 1:45–2:10: ネイルの強い痛み・変色で商品提案を停止する
5. 2:10–2:35: OrcaRouter、構造化メモリ、D1/R2、フォールバックを図で説明する
6. 2:35–3:00: LLMコスト、セキュリティ、事業展開を締める
