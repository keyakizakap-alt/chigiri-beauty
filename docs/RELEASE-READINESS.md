# CHIGIRI 美容AIエージェント：リリース改善記録

2026-09-12。対象は本リポジトリの実装。公開環境の監査完了を示すものではありません。

## 製品の方向性

5領域の相談を入口とし、手持ち確認 → 提案 → 利用者がプラン採用 → 日々の実行 → 振り返りを一つの体験として提供する。購入・予約・課金など外部への実行は利用者の明示操作を必要とする。

- 利点：既存の専門家チャット、商品情報、コンディション記録を活用できる。今回の実行記録は追加LLM呼び出しなし。
- 欠点：現在の今日のプランはルールベース。記録した実行結果から翌日の提案を調整する機能は未実装。効果の評価を行うものではない。
- 代替案：初期はスキンケアに対象を絞り、継続率・提案の納得度を検証してから他領域へ広げる。

## 今回実装した内容

1. 今日の提案を日付単位で保存し、実行チェック・直近30件の閲覧・記録の削除を可能にした。利用者単位のDB所有者条件を適用。上書き作成を拒否し、更新にはrevisionを使い衝突時409を返す。ゲストからログイン後の移行対象にも追加。
2. プラットフォーム認証ヘッダーの信頼を既定で無効化。Vercelでは明示設定されても無効。UIとAPIで統一。
3. 認証Cookieの不正エンコード・改ざんを拒否。署名鍵は32文字未満なら認証を無効化。
4. 変更APIの同一オリジン確認、実バイト数による読み込み上限、一般化したエラーメッセージ、チャットの構造検証を追加。
5. 画像台帳による所有権確認へ限定。クライアントが履歴へ書き込める旧URLは画像アクセス・削除権限の証拠として利用しない。JPEG/PNG/WebPのマジックバイトを確認。添付枚数をUI/APIとも2枚へ統一。
6. Turso上のトランザクション付き利用回数制限：利用者ごと10回/分、ゲスト20回/UTC日、ログイン100回/UTC日、全体1000回/UTC日。チャットリクエストを計数するため、ローカル応答や失敗も枠を消費する。OrcaRouterは25秒でタイムアウトして既存フォールバックへ。
7. Next.js / eslint-config-nextを16.3.5に更新。関連ロックファイルの修正版を反映。

## 構成のトレードオフ

| 選択 | コスト | 可用性 | 運用 |
| --- | --- | --- | --- |
| 今回：Tursoで履歴・プラン・利用枠を管理 | 追加サービス不要、各チャットにDB書込が増える | DB障害時はチャットを停止し上限保護を優先 | 管理先は少ないが容量・クォータ行の清掃が必要 |
| 代替：専用Redis＋WAF | 別サービスの費用・契約が増える | 利用枠処理を履歴DBから分離できる | 接続先・監視対象が増える |

利用回数上限は金額上限ではない。モデル選択・画像トークン・上流サービスの価格によって課金が変わる。

## 環境変数と運用

値はコミットしない。所有者は本リポジトリとホスティングの管理者。秘密値はホストの環境変数で管理し、漏えい疑い・管理者変更時にローテーションする。

| キー | 目的 / 範囲 |
| --- | --- |
| AUTH_SECRET | サーバーのみ。32文字以上のランダム鍵。変更で既存セッションは無効になる |
| GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET | Googleログイン。サーバー設定 |
| GOOGLE_REDIRECT_URI | 本番のコールバックを固定することを推奨 |
| TRUST_PLATFORM_AUTH_HEADERS | 既定false。Vercelではfalse。外部ヘッダーを除去する信頼済みゲートウェイ専用 |
| TURSO_DATABASE_URL / TURSO_AUTH_TOKEN | 永続データ。テストは独立DBを使用 |
| BLOB_READ_WRITE_TOKEN | 非公開画像。独立したテストストアで検証 |
| ORCAROUTER_API_KEY / ORCAROUTER_MODEL | AI生成。費用上限・アラートは提供元でも設定 |
| RAKUTEN_APPLICATION_ID / RAKUTEN_ACCESS_KEY | 任意の口コミ情報取得 |

リリース手順：PRの差分を確認 → 独立した検証用DB/ストアでプレビュー → 上表のP0確認 → ホストのデプロイ結果を確認。今回mainへのマージ・本番公開は行っていない。

新規テーブルは既存のensureAppStorage方式で作成される。Drizzle移行を使う環境では`0004_release_care_plans.sql`をアプリ初回アクセス前に適用し、二重作成を避ける。

ロールバック：認証失敗・所有権異常・継続的5xxで公開を停止し、既知の正常なリリースを管理者が再デプロイする。ただし今回閉じた認証・画像アクセス経路を再開しないよう、セキュリティ修正は保持する。追加テーブルは即時削除せず、復旧後に既存相談とケア記録を確認する。

API再検証：独立DBに対し`next start`を起動し、同じネットワーク環境で`SMOKE_BASE_URL=http://localhost:3000 node scripts/security-smoke.mjs`を実行する。本番URLは指定しない。
